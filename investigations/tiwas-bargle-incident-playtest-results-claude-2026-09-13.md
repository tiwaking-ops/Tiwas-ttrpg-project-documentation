# Tiwas — The Bargle Incident: Executed Playtest Results

This is a **real execution** of `tiwas-adventure-the-bargle-incident-2026-09-13.md`, using
`random.SystemRandom()` for every roll (not the illustrative numbers in the written module).
Source: `tiwas_bargle_playtest.py` (mechanics engine) + `run_playtest.py` (scenario runner).
Full per-roll data: `tiwas_bargle_playtest_rolls.csv` (202 rows) and
`tiwas_bargle_playtest_effects.csv` (63 resolved exchanges). Machine-readable summary:
`tiwas_bargle_playtest_summary.json`.

**Scripting conventions used** (documented in the engine's docstring, not presented as
rulings): effect declaration follows a fixed rotation per skill; DEC-102 "player chooses"
clauses are resolved by the same rng stream in this unattended run; Prone auto-clears at the
start of the Prone character's next turn; Armor Bypass matching is simplified to "target has
any `defense:armor` tag" rather than the full DEC-137 sub-zone address; S-11 healing restores
HP equal to the accumulated Margin total (DEC-074 leaves the exact conversion to GM
discretion — no fixed formula is ruled).

## Worked Examples Pulled From the Actual Run

**A real 100-Fumble creating a real Advanced Skill (Scene 2, Round 2):** Rowan rolls
**exactly 100** on Attack (Skill 29). Per Canonical §2.3, 100 auto-fails regardless of Skill
and always qualifies as a Double. Cost = 100 PE (his pool was 170, no Overflow). Failure XP =
max(0, 100−29) = 71. Skill Roll Pool cascade raises Attack from 29 to 31. The qualifying
failed Double creates **Power Strike** (bpp+bps, Tier 2, Cap 59) — this is the *actual*
Advanced Skill Rowan carries into Scene 3, generated by a genuine roll rather than the
illustrative example in the written module.

**DEC-106 self-Overflow risk, confirmed in practice (Scene 2, Round 1):** the Goblin, per
DEC-106(2)/(4), fires both its legal combat actions (Trip, then Crude Attack) back-to-back
on its own turn with no GM present. In Round 1 alone, four of its own rolls overflowed its
102-point Physical Energy pool: Trip (roll 62, overflow 10), Trip again (roll 72, overflow
38), Crude Attack (roll 57, overflow 23), Crude Attack (roll 41, overflow 7) — **78 points of
self-inflicted HP damage from its own resource shortfalls before it landed a single
attack.** DEC-106(4) explicitly flags this risk ("an NPC/creature may exhaust itself via its
own multi-attacks"); this run is a direct empirical confirmation of that warning actually
manifesting.

**DEC-103's carry rule fully negating a declared Effect (Scene 3, Rounds 1–3):** three
separate Wound declarations (two from Rowan against Bargle, one from Bargle against Rowan)
resolved to Magnitude ≤ 0 after Skill-Tier shred and margin de-escalation and were recorded
as `"Effect fully negated by shred + de-escalation (DEC-103 carry rule)."` — no Wound was
created, only the underlying contest itself (which still cost resources, still generated
Failure XP where applicable) actually happened. This confirms the "Tier floor 0 → Effect
negated" branch of DEC-103 fires under ordinary play conditions, not just in edge-case math.

## Findings — Genuine Completeness Gaps and Interactions Surfaced

These are observations about how the *ruled* mechanics interact when actually executed
together, not proposed rulings. Flagged for Tiwa's awareness; none of them are resolved here.

### Finding 1 — Skill "current" value is not auto-clamped when a Wound shrinks its Cap

The Goblin's Crude Attack ended the run at `Cap 37, current 40` — its own `bpp` attribute
was Wounded (−3) by Rowan mid-fight, which correctly recalculated the Cap downward per
DEC-004, but nothing in the corpus requires the already-set current Skill value to be
clamped down to match. This script deliberately did **not** invent a clamp (that would be
silent invention), so the character now sits "above Cap" purely from Wound-driven
Cap-shrinkage — a different mechanism from DEC-011.1's ruled "General XP may raise a Skill
above Cap" allowance, but landing in the same state. **Open question for Tiwa:** should an
Attribute Wound retroactively cap a Skill that now exceeds its shrunken Cap, or is
"above-Cap via Wound" an acceptable, unruled-but-not-prohibited state?

### Finding 2 — Wound location and Wound target-attribute are fully decoupled

DEC-102(2)'s literal reading selects the wounded attribute from the **attacking** skill's own
formula, while DEC-014/DEC-100 select the **location string** from the attacker's natural
roll via Zero-Step — two independent random processes. This run produced several
narratively odd but mechanically correct combinations: a "Torso" wound that reduced the
Goblin's `bsp` (Agility), a "Legs" wound that reduced Rowan's `mps` (Wits) via Bargle's Bolt,
a "Head" wound reducing Bargle's `bpp` (Might) via Rowan's Power Strike. Nothing is broken —
this is what the ruled formulas produce when composed — but it's worth flagging that the
corpus currently has no requirement (and arguably no mechanism) tying the *fictional* hit
location to the *mechanical* attribute being wounded.

### Finding 3 — Armor Bypass and its DEC-030 fallback are numerically indistinguishable

All 5 Armor Bypass declarations this run (2 Tag-matched against Rowan's Leather Armor, 3
falling back per DEC-030 against unarmored targets) resolved to **exactly the same
formula** — contest-delta Inflict Injury — because no ruled mechanic currently defines what
plain (non-bypassed) armor actually *does* to incoming Injury. DEC-058–062 establish Armor
as Tags/Traits, location-bound, resolved before Active Defense — but never supply a base
damage-reduction number for the ordinary (non-Bypass) case. This means, as implemented,
**declaring Armor Bypass currently has no observable mechanical consequence** distinct from
simply declaring Inflict Injury outright, on either resolution path. This looks like a real
gap in S-5 (Armor) rather than a scripting artifact — worth a dedicated ruling before Armor
Bypass is meaningfully testable end-to-end.

### Finding 4 — Ally-NPC Advanced Skill eligibility rests entirely on GM Fiat, with no corpus guidance

Aleena gained two Advanced Skills this run (`Smite (Advanced)`, `Iron Faith`) because this
script's `is_pc_like` flag was set `True` for her per the written module's GM Fiat framing
(DEC-130). Nothing in DEC-012/DEC-076/DEC-087 actually defines whether a recurring ally NPC
is closer to a "Player Character" (gets Advanced Skills from failed Doubles) or a "creature"
(pre-authored only, per DEC-087) for this specific purpose — the corpus's PC/creature binary
doesn't have a named third category for significant, named, player-adjacent NPCs. This is a
structural gap, not something this playtest can resolve on its own.

### Finding 5 — Repeated Advanced Skill creation cascades cleanly

`Power Strike (Advanced)`, Tier 3, was created when Power Strike itself (Tier 2) later failed
a qualifying Double — directly confirming DEC-012.4 ("Advanced Skills may themselves generate
further Advanced Skills... no arbitrary Tier ceiling beyond the natural 24-attribute limit")
functions correctly through at least two full cascade levels under real play conditions.

### Finding 6 — No runaway repeat-contest loops observed

Across 65 exchanges (including several genuine both-fail and exact-Quality-tie repeats), the
20-iteration safety cap built into the script was never triggered. This is reassuring but not
conclusive — it's one data point at this specific Skill range (roughly 25–65), not a proof
that DEC-013.4/13.5's repeat rule can't produce long chains at other Skill distributions.
