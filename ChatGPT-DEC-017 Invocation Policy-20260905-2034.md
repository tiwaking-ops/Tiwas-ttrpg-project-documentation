# 3. §5A - Final Provisional Wording

## 3.1 Proposed final §5A text

OpenCode should replace the existing draft §5A wording with the following text **without changing the underlying four-state model**:

### §5A. GM-Facing Procedure - Attack-Side Location Index Warrant

The four-state model in §2 is retained as the **internal/documentation architecture**. It records why a case is or is not eligible for Location Index generation and preserves the distinctions between established/resolvable, established/not-yet-resolvable, location-dependence-unresolved, and no-distinct-consequence cases.

The GM-facing procedure does not require the GM to classify the case into those four states during play.

> **Generate a Location Index only when the player has explicitly stated a distinct outcome beyond ordinary damage, that outcome's location-dependence is already established under current Tiwas design, and current Tiwas rules can actually resolve that location-dependent outcome.**

For this purpose:

1. **Explicit objective:** The GM does not infer an unstated distinct objective from location, attack description, fictional context, or cinematic framing alone.
2. **Distinct outcome:** The stated objective must identify a consequence beyond ordinary damage and must be tied to the specified location.
3. **Established location-dependence:** Location must already be an established delivery mechanism for that consequence under the current Tiwas design. A merely plausible future use of location does not establish warrant.
4. **Current resolvability:** A Location Index is not generated merely because a location-dependent outcome has been conceptually established. A current Tiwas rule must also exist that can act on the resulting Location Index.
5. **No warrant:** If any required condition is absent, no Location Index is generated.
6. **Internal state preservation:** The underlying four-state classification remains available for documentation, design analysis, and future subsystem development even though the GM-facing procedure is expressed as the single operational test above.

### Procedural riders

The following existing candidate-policy riders remain applicable:

- Compound objectives are evaluated disjunctively; a qualifying named branch can establish warrant for that branch.
- A stale objective does not establish warrant where the recorded fictional state no longer supports the stated consequence.
- In an S-1 opposed contest, only the winning participant's natural roll is eligible to supply the Location Index.
- Location Index evaluation may be deferred until a downstream stage requires the result because Zero-Step is a read-only post-process of the already-recorded natural roll.

### Scope limitation

This §5A procedure applies **only to attack-side Location Index invocation**.

It does not determine:

- whether a scene or campaign uses Location Tier 0, 1, or 2;
- the Tier-0 procedure;
- the Tier-2 procedure or cost;
- anatomical/component mapping;
- wounds;
- Effects;
- armour;
- defence;
- incapacitation or death;
- or any other downstream subsystem.

Those questions remain unresolved unless separately promoted.

### Proposed formal mechanic

**S-2 Attack-Side Location Index Invocation/Warrant**

For an attack-side resolution, a Tier-1 Location Index is generated only when all three conditions are satisfied:

| Gate | Requirement |
|---|---|
| W1 - Explicit Objective | Player explicitly states a distinct consequence beyond ordinary damage |
| W2 - Established Location Dependence | Current Tiwas design establishes that the stated consequence is delivered through location |
| W3 - Current Resolvability | Current Tiwas rules provide a mechanism that can resolve the resulting Location Index |

Formally:

$$
Generate(LocationIndex)=W1\land W2\land W3
$$

Where:

- `W1` = explicit distinct objective;
- `W2` = established location-dependence;
- `W3` = current resolvability.

If any gate is false:

$$
Generate(LocationIndex)=False
$$
